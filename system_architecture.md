The multi-agent design
Why multi-agent instead of one big agent?
A single agent handling maintenance, contracts, invoices, and comms simultaneously would have a bloated system prompt, get confused about which tools to call when, and be hard to debug. Multi-agent lets you give each specialist a tight, focused instruction set and a small, relevant tool list. The orchestrator's only job is to read the incoming message and decide who handles it.

Orchestrator agent
This is the entry point for everything. Every message — whether from the chat UI, a WhatsApp webhook, a PDF upload, or a cron trigger — hits this agent first. It does three things: classifies the intent (maintenance request? lease expiry? invoice submission?), pulls relevant context from Convex (which property, which tenant, current task state), and then calls handoff() to transfer control to the right specialist. It never does the actual work itself. In the OpenAI Agents SDK, handoff() is a built-in primitive that transfers both context and control to another agent cleanly — the specialist receives the full conversation history so it knows what's going on.

Maintenance agent
Triggered when a tenant reports a problem or the agent wants to schedule a service. Its flow is sequential: look up an approved contractor by type (plumber, electrician, cleaner) from the Convex contractor table, email them with the job details and ask for availability, then contact the tenant to agree on a slot, create a Google Calendar event for all parties, and after the job, send the tenant a verification prompt. The lookup_contractor(type) tool queries Convex directly — the property agent has pre-loaded their approved vendor list there. The email tool calls something like Resend or Nodemailer. Calendar uses the Google Calendar API.

Contract agent
Handles two separate flows. First: when a lease PDF is uploaded, it calls extract_lease_dates(pdf) — this sends the PDF to GPT-4.1 Vision which reads the document and returns the start date, end date, rent amount, tenant name, and property address as structured JSON. This gets written to Convex. Second: a Convex scheduled function runs daily, checks all leases, and fires a trigger to this agent for any lease expiring within 60 days. The agent then creates a calendar meeting between the property agent and the owner, follows up post-meeting, and if relisting is needed, collects the new rent and photos from the agent and calls post_propertyguru(data) — which is a Playwright browser script that logs in and fills the listing form. The photos are just the ones the agent uploads; no generation involved.

Comms agent
This is the coordination layer. It gets handed off to whenever another agent needs to reach a human — tenant, contractor, or owner. It holds the tools for WhatsApp (via Twilio's WhatsApp Business API or the Cloud API directly), email, and the ElevenLabs voice call. So it also whatsapps the contractors. The poll_availability(parties) tool is the most interesting one — it sends messages to multiple parties asking for their availability windows and waits for responses, then reports back to the Maintenance agent so it can create the calendar event. It also owns the reminder logic: if an agent hasn't approved an invoice after 3 days, it pings them.

Invoice agent
Triggered when a tenant submits a photo or PDF of something they paid for. ocr_invoice(image) sends the image to GPT-4.1 Vision with a prompt like "extract the vendor name, total amount, date, and category from this receipt." The result gets logged in Convex as a claim attached to the relevant property and task. The agent then notifies the property agent with a formatted summary and a one-click approve button. Once approved, mark_reimbursed() updates the record and the Comms agent sends the tenant a confirmation.

Tech stack choices
OpenAI Agents SDK — yes, this is the right choice and it directly targets the GPT-4.1/GPT-5.5 track prizes. The SDK gives you Agent, handoff(), Runner, and a built-in tracing dashboard at platform.openai.com where judges can literally watch your agents think in real time. That's a great demo moment. You define each agent as a Python or TypeScript object with a name, instructions (the system prompt), and a tools list. Handoffs between agents are just adding another agent to the handoffs list. It handles the turn loop, tool execution, and context passing for you. Use GPT-4.1 as the model for all agents.
Convex — your database, file storage, and cron scheduler all in one. The key reason to use it here is that Convex functions are reactive: when the Maintenance agent writes a new task to the database, your dashboard UI updates in real time without any polling. It also runs scheduled functions natively, which is how you implement the "check for expiring leases every morning" cron. Convex's file storage handles the PDFs and invoice photos — you get a URL back that you pass to GPT Vision. This directly targets the Convex prize.
Vercel — deployment in one command, and it hosts your Next.js frontend. Your Convex cron jobs run server-side so you don't need a separate backend server for anything except the Playwright script (more on that below).
Playwright — runs as a Node.js script, either in a Vercel serverless function with a headless Chromium layer, or more reliably as a separate small service (a basic Express server on Render or Railway). It logs into PropertyGuru, fills the listing form with the data the Contract agent collected, uploads the photos the agent provided, and submits. GPT-4.1 rewrites the listing description before submission.
Twilio / WhatsApp Cloud API — for sending WhatsApp messages programmatically. Twilio is easiest to set up in a hackathon (one account, one API key). The WhatsApp Cloud API (Meta's direct API) is free but takes longer to get approved. Decide based on how much setup time you want to spend.
ElevenLabs — you have 100k credits. Use their Conversational AI API to make outbound calls to contractors. The agent speaks, the contractor responds, and ElevenLabs transcribes the response back to text so the agent can process it. This is the most impressive demo moment and directly targets the voice prize.
